# ontology — 살아있는 규격·원장

청첩장 작업 중 참고하는 규격 지식의 단일 출처입니다. 여기 문서는 전부 "현재 참"이어야 합니다.
시점 기록(시안·조사 스냅샷)은 `references/`에 동결하고, 살아있는 문서에 섞지 않습니다.

## 원장 규칙

- ID(`REQ-*`·`D-*`·`Q-*`·`U-*`·`R-*`)는 이동·폐기 후에도 불변이고 재사용하지 않습니다. 폐기는 삭제가 아니라 상태 표기입니다
- 결정은 `decisions.md`의 D-* 원장(외부·크로스커팅) 또는 거기 색인된 논의록 결정 표에 등재합니다. 복제하지 않고 색인합니다. 정본에서 인용할 때 홈 네임스페이스 밖이면 접두가 필수입니다("부트스트랩 결정 1"). 뒤집힘은 새 번호 행으로 대체(supersede)하고, 옛 행은 "폐기 — D{n}으로 대체"로 표기합니다. 다른 논의록이 대체하면 "폐기 — {논의록}:결정 N으로 대체"
- 한 사실은 한 곳에만 씁니다. 다른 문서에서는 링크합니다. 절을 옮기면 원 위치에 "→ 이동" 포인터를 남깁니다

### 기계 검증 — `tools/check-refs.mjs`

위 규칙은 사람이 지키는 규약이라 어긋나도 조용합니다. `node docs/ontology/tools/check-refs.mjs`(의존성 0)가 그것을 시끄럽게 만듭니다. 살아있는 정본(`docs/ontology/` 중 `references/`·`tools/` 제외 · `docs/dashboard/` · 레포 루트 `CLAUDE.md` · `docs/artifacts/README.md`가 있으면)의 ID 인용을 전수로 뽑아 정의처에 해소되는지 봅니다. 동결본(`references/`)은 무편집 규칙이라 스캔 대상이 아닙니다.

검사 4종: ① 원장 ID 해소(`REQ-*`·`D{n}`·`Q{n}`·`U-{n}`·`R{n}`) ② `{접두} 결정 {n}`이 그 논의록 결정 표 안에 드는가 ③ 무접두 `결정 {n}`의 홈 네임스페이스. 논의록은 자기 표, 그 밖의 문서는 머리에 홈을 선언해야 하고(예: "결정 출처: `docs/dashboard/discussions/….md` 결정 표") 없으면 모호로 보고 ④ `decisions.md` 논의록 결정 색인의 "결정 수" ↔ 표 실제 행 수. 해소 실패·모호가 1건이라도 있으면 exit 1.

- 원장에 행을 넣고 빼거나, 논의록에 결정 행을 추가한 커밋에서 1회 돌립니다. pre-commit 훅이 자동으로 돌립니다
- 새 논의록을 열어 접두 어휘를 늘리면 `decisions.md` 색인과 스크립트 상단 `NS` 표를 함께 고칩니다. 안 맞으면 ④가 잡습니다
- 동결본을 정의처로 쓰게 되면 스크립트의 정의처 표에 그때 추가합니다

## 동결 기록 규칙 (references/)

- 파일명 `YYYY-MM-DD--{slug}.md`. 날짜는 스냅샷 기준일입니다. 파일명이 "그 시점의 기록"임을 선언합니다
- 본문은 편집하지 않습니다. 맨 위 상태 헤더(동결 표시 + 현행 정본 포인터)만 답니다
- 재조사 결과가 나오면 새 날짜 문서를 만들고 구본 헤더에 대체 포인터를 추가합니다
- 동결본의 값은 스냅샷 기준일의 사실입니다. 설계·구현 시 재검증 후 사용합니다
