# WIW-5 — 한 파일에 몰린 시안 적용 코드를 구조로 나누기

## 목적

시안을 즉시 반영하려고 `src/app/page.tsx` 한 파일에 장면 마크업 · 효과 · 자료를 모두 넣었습니다(WIW-4, 1175줄). 시안이 확정됐으니 읽고 고칠 수 있는 구조로 나눕니다. 화면과 동작은 한 군데도 바뀌지 않아야 합니다.

## 작업내용

- 장면을 구획(와이어프레임 쪽)마다 컴포넌트 파일로 나눕니다. 마크업은 조립본 `docs/artifacts/index.html`과 1:1로 두어 조립본이 바뀌면 그 파일만 고치면 되게 합니다.
- 효과(화면 높이 고정 · 진입 장면 · 쪽지 나타나기 · 덮개 · 카카오맵 · 마지막 장면 · 배경 음악 · 떠 있는 메뉴 · 알림)를 훅 파일로 나눕니다. 실행 순서는 지금과 같게 둡니다.
- 자료(성함 · 계좌 · 예식장 · 제목 · 설명 · OG 이미지)를 `src/content`로, 도구(클립보드 · 소리 페이드 · 카카오 SDK)를 `src/lib`으로 뺍니다. `layout.tsx`와 공유해 제목 · 설명이 한 곳에만 있게 합니다.
- 참조되지 않는 파일을 지웁니다(윈도 타일 설정 · 쓰지 않는 스크립트 둘 · 쓰지 않는 에셋 셋). 레포 첫 문서(`README.md`)의 스캐폴드 문구를 이 프로젝트 안내로 바꿉니다.
- 스코프 경계. CSS는 손대지 않습니다(`globals.css`는 조립본 산출물이고 정본은 조립본입니다). 조립본의 마크업 · 스크립트도 그대로 둡니다. 기능 추가 · 문구 변경은 하지 않습니다. 사진 파이프라인(`docs/scripts/images.mjs`)은 여전히 정식 이식 몫입니다.

## 주의할 점

효과 실행 순서가 화면에 영향을 줍니다. 화면 높이 고정(`--vh-fixed`)이 먼저 서야 커버와 마지막 장면의 치수 계산이 지금 값과 같습니다. 자식 컴포넌트의 효과가 부모보다 먼저 도는 것을 감안해 순서에 얽힌 훅은 페이지가 쥡니다.

리팩터링 전후를 기계로 대조합니다. 같은 조건(WebKit 390×844)에서 DOM · 구획 높이 · 계산된 CSS 변수 · 캡처 · 상호작용 상태를 모아 비교하는 탐침을 먼저 돌려 기준을 잡고, 끝난 뒤 같은 탐침으로 대조합니다.
