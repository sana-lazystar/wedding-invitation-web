# WIW-0 — 제목 (이야기 한 문장)

본문은 `docs/WRITER.md` 문체로 씁니다. 읽는 사람은 메인테이너입니다.

## 이야기

누가 무엇을 할 수 있게 되는지 씁니다. 이 장면이 실연되면 이야기가 끝납니다.
근거가 된 논의(discussion·미팅록)를 경로로 참조합니다.

## 범위

어디까지 만들고 무엇을 만들지 않는지 씁니다. 경계가 애매한 항목일수록 명시합니다.
하위 epic 목록은 여기에 베끼지 않습니다. `grep 'story: WIW-0' epics/`가 원본입니다.

## 인수 기준

메인테이너가 story 브랜치에서 직접 확인할 시나리오를 나열합니다.

- [ ] 시나리오. 화면 또는 API에서 확인하는 장면을 적습니다
- [ ] 하위 epic 전부 종결
- [ ] 인수 기록 기입 (확인 시각·방법)

## 주의할 점

유의할 점을 씁니다. 선행조건 대기는 `대기: {무엇}` 형식으로 적습니다(status에 blocked는 없습니다). 없으면 이 절을 지웁니다.

## PR 초안

인수가 끝나면 story→develop PR 초안을 남깁니다. PR 생성·머지는 메인테이너가 직접 합니다. 이 머지가 실배포 개시점입니다.
크로스레포 story는 레포별 초안과 머지 순서(deploy-order)를 함께 남깁니다.

본문 형식은 세 절입니다. 제목 한 줄, 작업 목적 요약 두세 문장, 작업 내용은 항목 목록입니다. 포괄 서술로 뭉치지 않고 task 단위 이하로 구체적으로 씁니다. 그대로 붙일 수 있게 펜스 블록으로 남깁니다.

```markdown
# 제목

{{ 한 줄 }}

# 작업 목적

{{ 요약 }}

# 작업 내용

- {{ 항목 }}
```
